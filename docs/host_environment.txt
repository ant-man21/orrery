# Host environment reference — native Linux (Ubuntu) setup
# Written after getting a fresh Ubuntu 22.04 host building/booting this repo,
# having previously only done so on Windows + WSL2. Dumping everything that
# mattered so the next fresh-host setup isn't a rediscovery exercise.

## OS
Distro   : Ubuntu 22.04.5 LTS (jammy)
Kernel   : 6.8.0-136-generic #136~22.04.1-Ubuntu SMP, x86_64
Disk     : needs a few GB free (QEMU source + build ≈ 2.7G, installed ≈ 560M)
CPU      : build uses all cores via `ninja -j$(nproc)`; 16 cores here

## QEMU — the gotcha
Ubuntu 22.04's packaged QEMU is 6.2 (1:6.2+dfsg-2ubuntu6.31, jammy-updates).
jammy-backports does NOT carry a newer qemu-system-x86 (checked — nothing
past 6.2 available via apt on this release).

OVMF's PlatformInitLib/Platform.c has a deliberate ASSERT(FALSE) when it
sees a "broken CPU hotplug register block" — a real QEMU bug, fixed
upstream in QEMU 8.0 (tianocore bugzilla #4250). QEMU 6.2 hits this every
time. This is why the same edk2 checkout booted fine on Windows/WSL2
(those environments had a QEMU 8+ already) but hangs/asserts natively on
stock Ubuntu 22.04.

Fix used: build QEMU 9.2.4 from source into a user-owned prefix, so the
distro package is untouched:

    prefix: ~/.local/qemu-9.2.4
    targets built: x86_64-softmmu, aarch64-softmmu (covers Q35Pkg + ArmVirtOrreryPkg)
    features enabled: --enable-gtk --enable-slirp --enable-tools
    (TPM, fdt, seccomp, libcap-ng all auto-detected as YES in this build)

Q35Pkg/qemu.sh and ArmVirtOrreryPkg/qemu.sh both auto-detect a binary at
~/.local/qemu-9.2.4/bin/qemu-system-{x86_64,aarch64} and prefer it over
whatever is on PATH. If that directory doesn't exist, they silently fall
back to the system qemu-system-* — so on a host that already has QEMU 8+
(e.g. a newer Ubuntu release, or WSL2), no source build is needed at all.
Check your version first:

    qemu-system-x86_64 --version

If it reports < 8.0.0, expect the assert and plan on the source build below.

## Packages needed

### To build edk2 / OVMF itself (from docs/setup.txt)
    sudo apt install build-essential uuid-dev iasl git nasm python3-distutils
Note: `iasl` here actually comes from the `acpica-tools` package on 22.04 —
apt resolves the `iasl` binary name to it automatically, nothing extra to do.

### Already on a typical Ubuntu desktop install (verify, don't assume on a
### minimal/server image):
    mtools (mcopy/mformat — qemu.sh uses these to build shared.img, no root needed)
    swtpm  (TPM emulation backend qemu.sh starts as a daemon)

### Only needed if you have to build QEMU from source (i.e. distro QEMU < 8):
    sudo apt install ninja-build meson pkg-config libglib2.0-dev \
      libpixman-1-dev libfdt-dev libslirp-dev python3-venv flex bison \
      libcap-ng-dev libseccomp-dev libgtk-3-dev python3-tomli

    (python3-tomli is required because Ubuntu 22.04 ships Python 3.10, whose
    stdlib has no tomllib — meson's config step needs it. python3-pip/
    ensurepip are NOT usable here either — Debian/Ubuntu disable ensurepip
    for the system Python — so this has to come from apt, not pip.)

## Building QEMU from source (only if needed — see version check above)

    curl -LO https://download.qemu.org/qemu-9.2.4.tar.xz
    tar xf qemu-9.2.4.tar.xz && cd qemu-9.2.4
    mkdir build && cd build
    ../configure --prefix="$HOME/.local/qemu-9.2.4" \
      --target-list=x86_64-softmmu,aarch64-softmmu \
      --enable-gtk --enable-slirp --enable-tools
    ninja -j"$(nproc)"     # ~15-20 min on 16 cores, full test suite included
    ninja install          # no sudo — everything lands under $HOME

Only the `sudo apt install` step above needs root. Downloading, configuring,
compiling, and installing QEMU itself needs zero sudo since the prefix is
user-owned.
